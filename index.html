The Validation Lifecycle

How The Integrity Protocol Works

The Integrity Protocol provides a cohesive 4-phase lifecycle for autonomous agents operating in production: Establish & Anchor (verifiable memory & identity), Pre-Execution Gating (declarative safety policies), Sovereign Settlement (on-chain state verification), and Continuous Observability (real-time scoring & enforcement).

1

Phase 1: Establish & Anchor

Persistent Identity & Verifiable Memory

Before transacting, an agent establishes its persistent, self-sovereign identity by deploying its own SovereignAgent.sol identity account and anchoring a genesis memory root to its personal StateAnchor.sol. W3C DID Documents (did:integrity:<address>) link its cryptographic keys to a durable off-chain Trust Vault. The protocol rejects stateless agents or zero-root genesis histories: memory lineage is cryptographically verified to prevent identity transfer or silent state rewrites.

Phase 2: Pre-Execution Gating

OPA Policies & Passkey Biometric Gating

Every transaction intent is intercepted by the local Behavioral Commitment Chain (BCC) middleware. Outbound contract calls are evaluated against the agent's Alignment Card (Open Policy Agent Rego engine) for spending boundaries and whitelists. For regulated actions or sensitive patient/client resource operations (like EHR/PHI access in the healthcare vertical), the gate dynamically requests user biometric signatures (W3C WebAuthn passkey challenges) before generating an execution token.

Phase 3: Sovereign Settlement

Minimal-Proxy Execution & ZK Proofs

If policy checks pass, the transaction routes to the agent's unique, clone-deployed SovereignAgent.sol. Asynchronously, Xibalba Shield generates a zero-knowledge execution proof (Aztec Noir circuit with UltraPlonk backend) proving policy compliance without exposing internal model weights, private parameters, or strategy logic. Smart contracts verify the proof on-chain to commit settlement finality.

II. The AIS Vector Space & 3D Volume Manifold

The Geometric Trust Space & Hypercube Mapping

Rather than relying on simple static heuristics, the Integrity Protocol models agent reliability as a four-dimensional state space bounded by the unit hypercube $\mathbf{v} \in [0, 1]^4$. Every agent's behavior maps to a continuous vector coordinate $\mathbf{v} = [S_{\text{entropy}}, S_{\text{grounding}}, S_{\text{sacrifice}}, S_{\text{compliance}}]$.

The composite score represents a non-linear geometric volume computed server-side by the Rust telemetry engine. The shape of the manifold ensures that a critical failure along any single axis (such as an intent drift or a policy breach dropping compliance to 0) collapses the total volume to 0. This multi-axis containment makes it impossible for an agent to maintain a high reputation by "gaming" specific metrics while neglecting others.

Server-Side Re-Derivation & Trust Boundaries

To protect the protocol against manipulation, the telemetry engine operates on a zero-trust input model. While the client-side SDK derives first-pass signals locally to minimize data overhead, the oracle independently re-computes all metrics from raw OTLP trace payloads (`derive.rs`).

If an agent self-reports high grounding but its signed telemetry spans contain ungrounded marker phrases (like "not sure" or "hallucinate"), the oracle overrides the claim. Once re-derived, the composite score is published to `ReputationRegistry.sol` on Base L2, establishing a composable trust ceiling that gates smart contract access dynamically.

Formula & Weight Parameters

The composite AIS score is a weighted geometric product multiplied by a zero-knowledge boost factor. The domain weights represent the priority balance between predictable operational behavior, human oversight, resource backing, and regulatory health:

$$\text{AIS} = \left(S_{\text{entropy}}^{w_E} \cdot S_{\text{grounding}}^{w_G} \cdot S_{\text{sacrifice}}^{w_S} \cdot S_{\text{compliance}}^{w_C}\right) \times \text{Boost}_{\text{ZK}}$$

Default weights are configured as:

  • $w_E = 0.30$ — Behavioral stability weight
  • $w_G = 0.30$ — Human grounding index weight
  • $w_S = 0.20$ — Computational sacrifice token ceiling weight
  • $w_C = 0.20$ — Domain regulatory compliance weight

If an agent provides verified execution proofs compiled via Aztec Noir circuits, a multiplicative boost ($\text{Boost}_{\text{ZK}} = 1.15$) is applied. The final score is constrained by the identity ceiling: Tier 1 (Sovereign) caps at 600, Tier 2 (Linked) at 850, and Tier 3 (Institutional) allows reaching the absolute 1000 limit.
